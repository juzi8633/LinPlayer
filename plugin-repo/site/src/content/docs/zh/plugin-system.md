LinPlayer 的插件不是「换个皮肤」那种插件。它拿到的是一组**接管位**:
应用把界面和数据流上的若干位置让出来,插件往里填东西,填完和内置功能长得一样、用起来一样。

## 能接管什么

- **数据源**(`dataSource`):自己定义一种「服务器类型」,填几个字段,之后浏览、搜索、播放全走你的实现。TVBox 兼容插件就是这么做的。
- **页面与侧栏**(`pages` / `sidebar`):新增一整页,挂到侧栏上。直播、规则编辑器、开发者工具都是独立页。
- **播放器覆盖层与侧边面板**(`playerOverlays` / `playerPanels`):在画面上画东西,或在播放页侧边开一块面板。字幕翻译的实时译文走覆盖层。
- **锚点插入**(`anchors`):往既有页面的指定位置塞一块自己的内容,比如详情页评分下面。
- **设置分区**(`settingsSections` / `settings`):设置页里多一段,或者只声明几个开关由宿主替你渲染。
- **主题**(`theme`):替换设计 token 与组件状态样式。结构和行为不变——主题包改不了交互。
- **命令与菜单**(`commands` / `menus`):右键菜单、命令面板、以及声明了 `external` 之后可被 `linplayer://cmd` 深链调用的入口。

## 跑在哪里

插件是 JavaScript,跑在应用内的插件运行时里,通过 SDK 和宿主通信。
UI 不是你直接画像素——你描述控件,宿主用原生控件渲染,所以插件页面在
Windows、Linux、Android 手机、Android TV 上长得都对,焦点和遥控器也都是通的。

## 它拿不到什么

- **账号凭据**。Trakt / Bangumi 这类账号在宿主里连,插件只借用已登录的会话,碰不到 token。
- **没声明过的能力**。局域网访问(`lan`)、需要的外部组件(`requires.components`)都要在 manifest 里写明,安装时摆给用户看。
- **别的插件的存储**。各自独立。

## 从哪开始

先在插件墙上装一个官方插件看看效果,再读[上架指南](/guide)。
每个扩展点在仓库的 `examples/` 下都有一个几十行的最小示例。
