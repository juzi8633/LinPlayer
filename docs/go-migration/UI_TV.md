## 1. 画布与单位

### 1.1 设计画布 = 960 × 540 dp

Android TV 的 1080p 设备约定是 xhdpi(1dp = 2px),720p 设备是 tvdpi —— **两者都是 960×540dp**。
本文所有数字都是这张画布上的 dp / sp,Compose 里原样写。

**旧草稿的数字不能照抄。** 旧 TV 把 1920×1080 当 CSS px 写死,运行时 `zoom = innerWidth / 1920`
(`rust-final:ui/tv/app/focus.ts:174-182`)——所以**旧稿的 1px = 1080p 面板上的 1 个物理像素 = 0.5dp**。
旧稿里的「按钮 52 / 17」在本文里是 26dp / 8.5sp。

### 1.2 旧稿的字号偏小,用 B 档【用户定 2026-09-14】

把旧稿换算过来之后,正文 8.5~10.5sp、次要信息 7~8sp。对照三家电视平台的下限:

| 平台 | 正文 | 次要 / 说明 |
|---|---|---|
| tvOS(HIG,1080p 下 pt = px) | 29px ≈ 14.5dp | 23px ≈ 11.5dp |
| Google TV(tv-material 默认字阶) | bodyMedium 14sp | bodySmall 12sp |
| 旧 TV 稿(换算后) | **8.5 ~ 10.5sp** | **7 ~ 8sp** |

旧稿比两家平台小了约 40%。当时用户否掉「标题 52–56、按钮 64/20」是对的(那一版确实把封面糊死了),
但评审是在 PC 显示器上看的 1:1 预览 —— 臂展距离看 17px 字正常,3 米外看不一定。

**定了用 B 档**。A 档留在草稿画廊里作对照(按菜单键切换),真电视上三米外再确认一次:

| token | **B 档(采用)** | A 档(旧稿换算,仅对照) | 用在哪 |
|---|---|---|---|
| `display` | 26sp / Bold | 18sp | Hero 片名、详情页片名 |
| `headline` | 22sp / SemiBold | 20sp | 页标题(「媒体库」「设置」) |
| `title` | 16sp / SemiBold | 13sp | 行标题、面板标题、服务器名 |
| `body` | 14sp / Medium | 9sp | 按钮字、列表项、卡片标题、正文 |
| `meta` | 12sp / Normal | 7.5sp | 年份、时长、副标题、说明 |
| `numeral` | 20sp / Bold | 15sp | 版本卡上的分辨率(三米外唯一一眼可辨的字段) |

**跟着字阶走的控件高度**(字变大了控件不跟,字就会顶出去):

| token | B 档 | A 档 |
|---|---|---|
| `controlH`(按钮 / chip / 输入框) | 40dp | 26dp |
| `rowH`(面板项 / 设置行最小高) | 48dp | 32dp |
| `iconS`(按钮内图标) | 20dp | 11dp |

**不跟着字阶走的**:封面尺寸、Hero 高度、导航轨宽度、间距 —— 它们是「布局元素」,
【用户定 2026-07-20】「10-foot ≠ 什么都放大,要放大的只是必须读的字」。

### 1.3 安全区

| 边 | 值 | 为什么 |
|---|---|---|
| 左右 | **48dp** | 画布宽的 5%。电视过扫描会裁 3~5%,旧稿用 32dp(3.3%)在 5% 过扫描的电视上会切字 |
| 上下 | **27dp** | 画布高的 5% |

- **背景可以出血**(Hero 图、详情页背景、视频),**文字和可聚焦件不许进安全区外**。
- 导航轨是唯一例外:轨的底色从 x=0 铺起,收起态图标中心在 x=32dp(§3.1)。
  【待真机】在开了过扫描的电视上看图标是否被切;被切就把轨整体右移 16dp。

### 1.4 分辨率与字体缩放

- 4K 电视在 Android 层仍是 960×540dp(系统按 xxxhdpi 出图),**不做第二套版式**。
- 跟随系统字体缩放(电视用户会调系统字号)。**所有带文字的容器高度用 `sp` 换算或 `wrapContent`**,
  不写死 dp —— 手机端栽过「系统字号调大,副标题被裁掉半行」(`Cards.kt:198-201`)。

## 2. 设计系统

### 2.1 色彩 —— 与手机端同一个品牌,强制深色

**强制深色,不跟随系统**【用户定 2026-07-20】。浅色主题在客厅是灾难。

**强调色用手机端的琥珀,不用旧 TV 的蓝**【用户定 2026-09-14】:同一个 APK、同一个图标,
手机上是琥珀、电视上是蓝,用户会以为装了两个应用。

| token | 值 | 用在哪 |
|---|---|---|
| `bg` | `#100E14` | 页面底。与手机 `LpColors.Dark.bg` 同值 |
| `rail` | `#0A090D` | 导航轨底。比 bg 更暗,隐进电视边框 |
| `surface1` | `#18161D` | 卡片占位、行底、下载行、服务器卡 |
| `surface2` | `#211E28` | 面板、对话框、OSD 上的每个控件 |
| `surface3` | `#2C2834` | 未选中的 chip、输入框底 |
| `line` | `#2E2A36` | 分割线 |
| `fg` / `fg2` / `fg3` | `#F3EFF8` / `#9B93AE` / `#6E6880` | 三级文字。与手机同值 |
| `focus` | `#F3EFF8` | 焦点填充 / 焦点环(= fg) |
| `onFocus` | `#16131B` | 焦点填充上的文字 |
| `acc` | `#F5A524` | 选中、进度、主按钮常态、「当前」 |
| `accDim` | `#F5A524` @ 18% | 选中态的底 |
| `onAcc` | `#20160A` | 琥珀底上的文字 |
| `ok` / `warn` / `bad` | `#5CD6A0` / `#F5C04A` / `#FF6B5E` | 在线 / 可能匹配 / 失败 |
| `scrim` | `#100E14` @ 62% | 详情页背景图上的**均匀**遮罩 |

☠ **TV 上没有半透明的 surface。** 手机端的 `s1/s2/s3` 是半透明白(「分层替代描边」),
叠在电视的封面或视频上就成了看不清边界的一层雾。
【用户定 2026-07-20】压在画面上的东西**要么全透明,要么不透明块**。

`warn` 与手机不同:手机的 `warn` 就是 `acc`(同一个琥珀),而 TV 上「可能匹配」黄标和「当前」琥珀字
会出现在同一张版本卡上 —— 同色就分不出来,所以 TV 的 `warn` 往黄偏。

### 2.2 渐变、模糊、遮罩 —— 每一处都是用户定过的

| 位置 | 做法 | 出处 |
|---|---|---|
| 首页 Hero 上的文字 | **什么都不加**:不加渐变、不加底、不加描边、不加阴影 | 【用户定 2026-07-20】旧稿试过描边、不透明块、八向硬描边三版全否(`rust-final:ui/tv/theme/tv.css:228-240`) |
| 详情页整页正文 | 背景图上盖一层**均匀** `scrim`,不是渐变 | 【用户定 2026-07-20】「不然看不清字真的很伤」 |
| 播放页 OSD | 上下栏**全透明**;每个控件、标题、时间码**自带不透明底**(`surface2`) | 【用户定 2026-07-20】 |
| 集数栏两端 | **不做渐隐** | 【用户定】「有一块黑色的东西挡住,好恶心」(`tv.css:1172-1175`) |
| 面板 / 对话框 | 不透明底 + 阴影,**无黑色遮罩、无毛玻璃** | 【用户定 2026-07-20】视频要大部分露在外面 |

**首页和详情页的做法相反,不许互相照抄**:Hero 只有左下角一小块字,用户明确不要兜底;
详情页是整页正文压在背景上,用户明确要。

### 2.3 形状

| token | 值 | 用在哪 |
|---|---|---|
| `r.sm` | 6dp | 按钮、chip、输入框、集号 chip、时间码底 |
| `r.md` | 10dp | 卡片封面、面板项、版本卡、Toast |
| `r.lg` | 14dp | 面板、对话框、Hero、服务器卡 |
| `r.pill` | 999 | 状态点、指示点、开关、头像 |

### 2.4 间距

`0 2 4 6 8 12 16 20 24 32 48`(dp)。**只有这些值**,第十二种先改这张表。
大于 48 的偏移(Hero 高度、OSD 让位)抽成具名常量,不写字面数字。

### 2.5 图标

**直接用手机端 `LpIcons`**(线性族,24 视野,stroke 1.9,`apps/android/.../ui/theme/Icons.kt`)。
TV 需要而手机没有的四个新增到同一个文件,**不开第二套**:
`skipPrev`(上一集)、`skipNext`(下一集)、`chapter`(章节)、`qr`(二维码)。

【用户定 2026-07-20】**图标按钮必须带文字**(用户看到裸图标方块直接问「那是什么」)。
唯一例外:播放页左组(上一集 / 快退 / 播放 / 快进 / 下一集)是通用约定,可以纯图标。

## 3. 外壳与导航

### 3.1 导航轨【用户定 2026-09-14:收起只剩图标,焦点进轨后展开并盖在内容上】

```
收起(焦点在内容区)                      展开(焦点在轨上)
x=0   64                                x=0             200
┌────┬───────────────────────────┐     ┌────────────────┬──────────────┐
│ ◆  │ ← 内容区左边线 x=96        │     │ ◆  LinPlayer    │              │
│ ⌕  │                           │     │ ⌕  搜索          │  内容不动,   │
│ ▣⌂ │ ← 当前页:琥珀底琥珀图标    │     │ ▣⌂ 首页 ▣        │  被盖住一截  │
│ ▦  │     内容区 816 × 486       │     │ ██ 媒体库 ████ ← 焦点:反白      │
│ ♡  │                           │     │ ♡  收藏          │              │
│ ↓  │                           │     │ ↓  下载          │              │
│ ── │                           │     │ ─────────────   │              │
│ ☰  │                           │     │ ☰  服务器        │              │
│ ⚙  │                           │     │ ⚙  设置          │              │
└────┴───────────────────────────┘     └────────────────┴──────────────┘
```

| 项 | 收起(焦点在内容区) | 展开(焦点在轨上) |
|---|---|---|
| 宽 | **64dp** | **200dp,盖在内容上面**,内容区不动、不重排 |
| 轨项 | 48×44dp,只有 22dp 图标 | 184×44dp 横条:22dp 图标 + 间距 12 + 文字 `body` |
| 品牌块 | 28dp logo | logo + 「LinPlayer」`title` |
| 底色 | `rail`,右侧 1dp `line` | 同左,另加阴影 elevation 8(压在内容上要分得出边) |
| 过渡 | — | 宽度 64→200,180ms `LpEasing.emphasized`;收起反向 |

| 项顺序 | 搜索 → 首页 → 媒体库 → 收藏 → 下载 · 弹簧 · 分隔线 · 服务器 → 设置 |
|---|---|

- 内容区左边线 x=96dp(轨 64 + 32),内容宽 **816dp**。
- 这是【用户定 2026-07-20】「图标按钮必须带文字」的**唯一例外**:收起态没有文字,
  但焦点一进轨文字就出来 —— 用户看得到文字的时刻,正好是他要在轨上选的时刻。
- **展开时盖在内容上,不把内容往右推**:推的话每次进出轨整页都要重排,焦点卡也会被挤走。
- 展开**不加遮罩**(和侧面板同一口径)。
- 轨上每多一项,底部的「设置」回「首页」就多按一次(2026-09-14 把排行榜 + 放送表合成「发现」一项就是为此;2026-09-19 整项随宿主功能删除)。

**轨项的状态**

| 状态 | 收起 | 展开 |
|---|---|---|
| 常态 | 图标 `fg3` | 图标 + 文字 `fg2` |
| 当前页(未聚焦) | 底 `accDim`,图标 `acc` | 底 `accDim`,图标 + 文字 `acc` |
| 聚焦 | —(焦点一进轨就展开) | 底 `focus`,图标 + 文字 `onFocus`;**不放大**(会撑破轨宽) |

**轨的焦点规则**

- 内容区最左一列按 ← 进轨:轨展开,**焦点落在当前页那一项**,不是上次停过的项(旧实现 `Rail.tsx:13-20`)。
- 轨上按 → 回内容区:轨收起,**焦点落回离开时的那个元素**。
- 轨项按 OK = 切页并收起;**光把焦点移到轨项上不切页**(不做「预览式切换」—— 焦点路过「设置」时整个内容区换掉,再按 → 就进了设置)。

### 3.2 全屏页(不画轨)

播放页、剧/电影详情、季详情、集详情、首次启动。它们占满 960×540,内容自己守 48/27 安全区。

### 3.3 路由与返回栈

- **轨上的页互为平级**:从轨切页 = 返回栈重置为 `[首页, 目标页]`;切到首页 = `[首页]`。
- **下钻入栈**:详情、集详情、播放、线路管理、带库 id 的媒体库、本机文件夹的子目录、添加服务器。
  - ☠ 线路管理有轨但必须入栈 —— 当平级处理的话从服务器页进去按返回会直接退出应用(`rust-final:ui/tv/App.tsx:51-52`)。
  - ☠ 首页库行标题进的媒体库必须入栈 —— 当平级处理会清栈,按一下返回就退出应用(`App.tsx:53-55`)。
- **集详情页里用集数栏换集不入栈**:切了 8 集,按一次返回就回剧详情。

### 3.4 返回键 —— 单一出口,四级

**所有返回都从一个地方分发**,由内到外问,**第一个说「我吃了」的就停**:

| 级 | 谁 | 行为 |
|---|---|---|
| 1 | 对话框 / 操作面板 / 侧面板 | 关掉它,焦点回到打开它的那个元素 |
| 2 | 页内模式 | 排序模式 → 还原并退出模式;播放页 OSD 显示中 → 收起 OSD |
| 3 | 路由栈深 > 1 | 弹一层 |
| 4 | 栈底(首页) | 屏幕底部 Toast「再按一次返回退出」,**2 秒内**再按才退出 |

- ☠ 旧实现在这里出过三个 bug,都是「两个监听同时收到返回键」:面板开着按返回,**面板没关、页面先退了**;
  播放页第一下返回就退页且**没调 `player.stopPlayback`**;OSD 收起时按返回连退两层
  (`rust-final:ui/tv/App.tsx:71-81` + `pages/PlayerPage.tsx:161-195`)。
  Compose 里用嵌套的 `BackHandler`,**页面自己不许再监听 `KEYCODE_BACK`**。
- 第 4 级不用确认对话框【用户定 2026-09-14,推翻旧稿】:对话框默认焦点在「取消」,退出要 → + OK 两次;
  「再按一次」只多一次,而且不打断画面。

## 4. 焦点与按键

> 旧 TV 的焦点是自己用第三方空间导航库搭的,§13 列出的补丁在 Compose 下全部不需要。
> **但这一节的每条行为要求都继承** —— 它们是产品规则,不是实现细节。

### 4.1 焦点态 —— 焦点和选中走两条通道

旧实现最大的视觉问题:**选中态和焦点态都用描边**,选中且聚焦的版本卡、季 chip 焦点环被吃掉,
「筛选与排序」入口聚焦时**没有任何视觉变化**(`rust-final:ui/tv/theme/tv.css:599-603,1130-1133`)。

本文定死:**焦点 = 白(反色填充或白框),选中 = 琥珀**。两条通道互不借用。

| 族 | 常态 | 聚焦 | 选中(未聚焦) | 选中 + 聚焦 |
|---|---|---|---|---|
| **A 卡片**(海报 / 横卡 / 版本卡 / 服务器卡) | 封面 | 放大 **1.06** + 封面外 2dp `focus` 框 | 版本卡:底 `accDim` + 1.5dp `acc` 框 | 放大 1.06 + 2dp `focus` 框(**白框压在琥珀框外面**,两个都看得见) |
| **B 实体控件**(按钮 / chip / 轨项 / 面板项 / 设置行) | 底 `surface2`,字 `fg2` | 底 `focus`,字 `onFocus`;按钮与 chip 放大 1.04,**行不放大** | 字 `acc` + 行首 3dp `acc` 竖条 / chip 底 `accDim` + 文字下 16×2dp `acc` 短横 | 底 `focus`,字 `onFocus`,**竖条 / 短横保留为 `acc`**(反白之后这是唯一能看出「焦点所在的就是选中那个」的记号) |
| **C 主按钮** | 底 `acc`,字 `onAcc` | 底 `focus`,字 `onFocus`,放大 1.04 | — | — |
| **D 进度条** | 高 4dp,旋钮 13dp | 高 7dp,旋钮 20dp + 3dp `bg` 暗环 | — | — |
| **E 输入框** | 底 `surface3` | 2dp `focus` 框 + 光标;**聚焦即拉起输入法** | — | — |
| **F 展示块**(简介、演职人员、媒体信息) | 无 | 1dp `fg3` 框,外扩 8dp,**不放大** | — | — |

- **1.06 不是 tv-material 默认的 1.1**:放大的只是封面,标题在封面下 6dp。
  165dp 高的海报放大 1.1 上下各长 8.25dp,压住标题;1.06 长 4.95dp,刚好不压。
  (Google TV 设计指南给的是按尺寸分 1.025 / 1.05 / 1.1 三档,大件取小值。)
- **进度条旋钮加暗环**:常态的白旋钮会和白色缓冲段糊在一起,而「当前位置在哪」是焦点落在进度条时唯一要传达的信息(`tv.css:850-851`)。
- **F 族存在的理由**:滚动是焦点驱动的,**最后一个可聚焦项下面的展示区块永远滚不到,等于不存在**
  (用户:「我根本无法往下点,完全看不了」,`pages/EpisodePage.tsx:664-671`)。框刻意做弱,一眼看出「这不是按钮」。
- 放大动画走 `LpSpring.snap`(damping 0.9);**不做动画阴影**。
- **按下态**:OK 按住期间缩到 0.98,松开弹回。
- **反白之后,行内的状态色一律让位给 `onFocus`**:下载行的「41%」、线路行的「86 ms」这类琥珀 / 绿 / 红字,
  压在白底上对比度只有约 2:1(草稿出图后发现)。只有竖条、短横这类**形状**记号保留原色。
- **导航性质的列表(设置分类)选中只画竖条,不画勾**:勾读作「已勾选」,而那里的意思是「正在看这一类」。
- **Lazy 容器一律裁剪到自己的边界**:网格和横向行要往两侧各出血 12dp 并配同样大小的 `contentPadding`,
  否则第一行 / 第一列的放大 + 白框被切掉一截(草稿出图实测)。

### 4.2 焦点不许丢,不许被抢

| 规则 | 场景 |
|---|---|
| 面板 / 对话框关闭 → 焦点回打开它的那个元素 | 面板一卸载,焦点在树上没有落点 = **遥控器整个失灵**,TV 最经典的 P0 |
| 返回列表页 → 焦点回刚才点进去的那张卡,滚动位置不变 | 旧实现两处都没做到(从详情回媒体库回到第一行、回首页回到 Hero) |
| 异步回来的内容**不许 `requestFocus`** | 版本卡回填、放送表回来,抢焦点会偷走用户已经落在「播放」上的焦点 |
| 列表数据替换(换筛选、换季)后,焦点落在新列表第一项 | 焦点停在一个已经不存在的节点上 = 失灵 |
| 页面内切换(设置换分类)**焦点留在左栏** | 右栏跟着换,焦点跳过去的话连续浏览分类很烦 |
| 不可用的项**保留但不可聚焦** | 消失会让用户以为东西丢了;可聚焦又白按一次方向键 |

### 4.3 滚动跟随

| 容器 | 规则 |
|---|---|
| 横向行 | **焦点项左缘钉在行首**(内容区左边线);行尾不足一屏时不再滚,最后一张贴右边线【用户定 2026-09-14,手感待真机】。**必须显式提供 `LocalBringIntoViewSpec`** —— 真电视上 Lazy 列表的默认值是「焦点项停在 30% 处」,而手机、截图环境里不是,不显式给的话草稿图和真机长得不一样(`foundation 1.12.0 BringIntoViewSpec.android.kt:37-49`) |
| 首页(一行一段) | **焦点卡钉在距顶 64dp**(= 安全区 27 + 行标题 29 + 间距 8),上下一样,行标题跟着露出(草稿 02);Hero 整块请求露出,滚动被 0 夹住 = 第一段贴真顶 |
| 详情类纵向页 | 往上:**对齐焦点所在「段」的顶**(段 = Hero / 一整行含行标题);第一段贴到真顶。往下:只保证焦点项完整露出,**封面下的两行字(`TvDim.captionH`)算在里面** —— 焦点节点只有封面,不算的话标题被切在屏幕下沿 |
| 网格 | 焦点行保持在可视区从上数第二行的位置;第一、二行不滚【待真机】 |
| 面板 | 焦点项完整露出即可 |

- 往上对齐段顶是用户报过的:只保证焦点项露出时,从下往上回到 Hero,停在「播放按钮顶端」,
  上面 200dp 的封面在视野外(「从下往上一滑就缺失内容」,`components/Focus.tsx:415-423`)。
- **焦点项放大后的边不许被裁**:行容器不 clip,左右靠 `contentPadding` 让出 ≥ 12dp。

**播放页**

  OSD 收起时树上没有别的可聚焦件 —— 不这么做的话「整屏黑着按什么都没反应」。
- **确认键同时认** `DPAD_CENTER` / `ENTER` / `NUMPAD_ENTER` / `BUTTON_A`(Android TV 官方按键语义表),

- **媒体键只处理一次**:TV 第一版**不启用** `MediaSession`(没有后台播放),媒体键在播放页根节点处理。

- 退出播放用「再按一次」而不是对话框【用户定 2026-09-14】,理由同 §3.4 第 4 级。

### 4.5 文本输入【用户定 2026-07-21】

- **焦点框就是输入框**:焦点到达即拉起系统输入法,**不需要再按一次确认**;上下键照常换字段。
  用户原话:「你选中的框和输入框可以分开的?这是为何」。
- **不自建虚拟键盘**:Android TV 有系统输入法,白拿语音输入和外接键盘;自建还得维护中文候选。
- **系统键盘盖住下半屏** → 要输入的框和历史全放在上半屏(y < 270dp)。
- 提交时机 = 输入法的「完成」键或失焦,**不是每个字**(每字一次 `prefs.setProxy` 会把半截主机名落盘)。
- 离页时正在输入的内容**也要提交**,否则改动静默丢失。
- ★ **首次启动页初始焦点故意不放在输入框上**:焦点一落上去输入法就升起盖住半屏,而那一页的主路径是扫码。
- **实现口径**:用 `BasicTextField(value: String, …)` 这个旧重载,聚焦时再手动 `keyboardController.show()`。
  - 旧重载自带「遥控器方向键直接移出输入框」(`foundation 1.12.0 TextFieldFocusModifier.android.kt:40-77`);
  - 新的 `BasicTextField(TextFieldState)` **没有这层拦截**,遥控器 ↑↓ 会被当成光标移到行首行尾吃掉 —— 正是旧 TV「进了输入框上下键就失灵」那一类。
  - tv-material 1.1.0 **没有任何输入框组件**,样式自己画(族 E)。
- 【待真机】Gboard for TV / 厂商输入法在聚焦即 `show()` 时是否真的升起、升起后方向键归谁。

## 6. 反馈层

### 6.1 三种失败,三种画法

| 失败的范围 | 画法 |
|---|---|
| 整页拿不到(详情页主数据、媒体库首屏) | `FullState`:「没加载出来」+ 原因 + 「重试」按钮(已聚焦) |
| 页面的一块拿不到(首页某一行、Hero) | 那一块位置上 `InlineError`,**其它块照常画** |
| 一次动作失败(收藏、切线路、设置落盘) | `Toast` 原因原话 + **UI 回滚到动作之前** |

- ☠ **失败和加载中必须是两个状态**。旧实现首页 Hero、媒体库库表、收藏页都是「失败时 data 仍为空,页面只判空」
  → 失败的块**永远停在骨架上**,用户以为还在加载。
- **错误说两行**:第一行给用户看(「无法播放这个文件」),第二行给排查用(「服务端返回 500 · 转码进程未启动」)。
- 错误码到 UI 的映射【继承手机 `AppState.report`】:`E_UNSUPPORTED` / `E_SHUTDOWN` / `E_NETWORK` 静默,其余 toast `advice`。

### 6.2 空态

**空态必带出路**:一句话 + 一个已聚焦的按钮。**「空」分三种,文案不同**:

| 情况 | 文案 | 按钮 |
|---|---|---|
| 确实没有 | 「还没有收藏」 | 「去媒体库看看」 |
| 被筛掉了 | 「当前筛选下没有内容」 | 「清除筛选」 |
| 搜不了(接口失败)| 「搜索失败:原因」 | 「重试」 |

- 首页的行、详情页的相似推荐、演职人员:**空就整段不画,连标题一起**(「继续观看(空)」只是占位噪音)。
- 列表滚到底:最后一行下面一行 `meta fg3`「已经到底了 · 共 N 项」。

### 6.3 加载

- **骨架先出,各块各自到位,不设屏障**【继承 SPEC §8.0】。等齐再画 = 机顶盒上整屏黑到像死机。
- **返回一个页面不许整屏重新骨架化**:用手机端的 `PageCache.keepState` 留住上一次结果,
  后台静默刷新(用户报的「每次打开都要更新」就是这一下空屏,`pages/HomePage.tsx:32-33`)。
- 冷启动(会话判定没完成):画首页骨架,**不画转圈、不先画登录页再跳走**。

## 7. 页面规格

> 每页按同一个顺序写:**版式 → 焦点(初始 / 特殊跳转)→ 数据 → 状态 → 坑**。
> 页面之间通用的东西(返回栈、焦点态、空态口径)不再重复,见 §3–§6。

### 7.0 启动【继承 `SPEC.md` §8.0】

- TV 根(`TvRoot`)和手机根共用同一个 `AppState`,自己再 `provide` 一次 `LocalApp`。
- `loggedIn == null` → 首页骨架(带轨);`false` → 首次启动页(§7.1,**不画轨** —— 轨上八项都点不动);`true` → 外壳。
- 删掉最后一台服务器 → `account.status` 事件 → 回到首次启动页。
- 手机遥控添加服务器成功 → 同一个事件 → 首次启动页**自己换走**,不轮询、不自己跳页。

**焦点**:初始 = Hero「详情」。从详情页返回 → 回到刚才那张卡,行的滚动位置不变。

**数据与状态**

- 五块**各自并发**,各自骨架、各自出错(§6.1)。先 `PageCache` 留存再后台刷新。
- 空行整行不画(连标题);**Hero 拿不到**:整块换成 `surface1` 底 + `InlineError`,下面的行照常。
- 全部为空(新服务器):`FullState`「这台服务器上还没有内容」+「去服务器页」。

- **不出现的项**:主题(强制深色)· 界面字体 · 截图 / 截长屏 · 画中画 / 后台播放 · 外部播放器 · 版本 / 字幕 / 音轨**正则**(遥控器上写正则是灾难)· 图标库 · 详情页模糊强度。

  ☠ 选「自动」要传 null,**不许传空串**(空串会让选轨去匹配空语言码 →「设了自动却一条音轨都选不中」)。
- 代理类型为「不使用」时本组其余项隐藏。
- 「立即检查更新」三种结果分开:「已经是最新版本」/「有新版本 x」/「检查失败:原因」【继承 PC A-5】。
- **每组各自加载**,没回来的组画骨架行;账号类状态没问到时**不许画成「未连接」**(否则每次进页闪一下)。
- 焦点:初始 = 左栏第一项;左栏 OK 切分类,焦点**留在左栏**;右栏按分类整体重建(否则上一类最后的焦点被记到新一类同序号的行)。

### 7.14 本机文件夹【用户定 2026-09-14】

**两个页面**:挑文件夹(添加源时)· 浏览文件夹(已添加的本机源)。

**挑文件夹**(入栈)

- 第一层 = 存储卷列表(系统 `StorageManager`):「内部存储」+ 每个 U 盘 / SD 卡(卷名 + 容量)。
  **这一层归 UI**:它是「系统文件选择器」的职责(`SPEC.md` §8.5),Android TV 上大多数设备**没有**系统自带的文件夹选择器。
- 进入卷之后逐层列子目录(行 + 面包屑);顶部一个主按钮「选择这个文件夹」。
- 选定 → `source.login {kind:"local", base_url:<路径>}` → 回到服务器页,新卡片出现(图标 = 文件夹)。
- 权限:**进这一页的那一刻**才申请(`READ_MEDIA_VIDEO` / 旧版 `READ_EXTERNAL_STORAGE`);拒绝 → `FullState`「没有读取视频的权限」+「去系统设置」。
- 【待真机】U 盘在各家电视上的挂载路径能否用裸路径读到;列目录时非视频文件是否被系统隐藏。

**浏览文件夹**(当前源是本机文件夹时,「媒体库」导航项进的就是这一页)

- 面包屑一行,每段可聚焦,OK 跳到那一层;子目录入栈,**返回键回上一层**(不再放一行「‹ 返回上一级」占焦点位)。
- 列表单列,行高 56dp:图标 · 名称 `body`(**长文件名换行,不截断**)· `meta fg3`「8.4 GB · 2024-07-12」。
- **只列目录和视频文件**(`source.listDir` 回的 `is_video`),封面图、nfo 之类不列。
- 视频 OK → `source.play` 进播放页;长按 / 菜单 → 面板:从头播放 · 继续播放(有记录时)。
- 首页在本机源下:`FullState`「本机文件夹没有首页推荐」+「打开文件夹」。
- U 盘被拔:`FullState`「找不到这个文件夹」+ 第二行「U 盘可能被拔掉了」+「重试」。
- ★ 核心层对传回来的路径做了越狱闸(`core/source/local/local.go` 的 `confine`):**UI 不许自己拼路径绕过 `source.listDir`**。

### 8.3 进度条上的遥控器手感【用户定 2026-09-14】

- 焦点在进度条上按 ←/→ **不立即 seek**:移动一个**预览游标**(游标上方显示目标时间 + 章节缩略图 `player.thumbnail`,没有就只显示时间)。
- 松手 700ms 后,或按确认,才发 `player.seek`。
- 按住加速:第 1~3 次 10s(= 快进步长)→ 30s → 1min → 5min。
- 理由【继承 PC A-17】:seek 是排队命令,每按一下发一次会把命令队列灌满(「拖着拖着卡住」),而且进度条先弹回原处再跳到新位置。
- 时长未知(`duration == 0`)时进度条**不可聚焦**,游标不许用 0 当量程(量程塌成 1 秒 → 「点了跳转画面没动」)。

### 8.5 起播、跳过、下一集、收尾

**起播**

- 进页**同步**立起黑幕,再异步取流【继承 PC A-14】;撤黑幕的判据是「时间真的往前走了」,不是 `position > 0`【继承 PC A-15】。
- 兜底:4 秒且不在缓冲 → 撤;**12 秒无条件撤**(`PlayerPage.kt:403-415`,状态事件发不出来时 `buffering` 会停在初值 true)。
- 黑幕上:32dp 转圈 + 下方缓冲速度。

**跳过片头 / 片尾**

- 数据 `player.getSkipRange`;开关在设置和「更多」面板里各有两行。
- 进入片头区间:右上出现「跳过片头 ›」按钮,**OSD 收起时也出现**,停留 8 秒;**OSD 收起时按确认 = 跳过**(此刻按确认最可能的意图)。
- 「到点自动跳过」开着就不出按钮直接跳,Toast「已跳过片头」。
- **每片各跳一次**:用户倒回去看片头不许被再踹走;**片尾只在后面还有内容时才跳**【继承 PC A-18】。

**下一集**【用户定 2026-09-14】

- 播完(`eof`)且有下一集且「自动播放下一集」开着:右下出现下一集卡(缩略图 + 「下一集 E07 · 集名」+ 5 秒倒计时环),
  焦点落在卡上;OK = 立即播放,返回 = 取消并退出播放页;**倒计时走完不按键 = 自动播下一集**。
- 「自动播放下一集」关着:照样出下一集卡,但**没有倒计时、不自动播**,只等 OK。
- 没有下一集:退回集详情页,Toast「播放完毕」。

**收尾**

- `keep-open` 下核心层永远不发 END_FILE,判播完读 `eof`;**`eof` 为真只收尾一次**(加锁)。
- 播完落库传**总时长**,不传当前时间(差零点几秒 = 99% = 服务端不算看完,Trakt/Bangumi 一次都不触发)【继承 PC A-19】。
- 从没往前走过就 `eof` = **起播失败**,走失败页,不许静默退回。
- 退出链路 `落库进度 → 离页`,**落库失败也要离页**【继承 PC A-12】;收尾挂在 `app.bg` 上(页面的协程作用域正被取消,挂在它上面的上报一件都不跑)。
- 按电视遥控器的主页键离开应用 → 暂停 + 落库进度 + 停止播放(**TV 不做后台播放**)。

### 8.6 故障与失败

| 情况 | 画法 | 按钮 |
|---|---|---|
| 起播失败 / 放不出来 | 全屏失败页:「无法播放这个文件」+ 第二行技术原因(核心层原话) | 重试(聚焦)· 换内核重播 · 线路管理 |
| 有声音没画面 | 居中故障牌(`surface2` + 2dp `bad` 框):「只有声音,没有画面」+ `player.opts` 分诊出的原因(vo 没建 / 没解出帧 / 被挡) | 无(返回键退出) |
| 跳转很慢 | 居中故障牌:「这台服务器不接受 HTTP Range 请求,跳到未缓冲的位置要等它把中间的数据下完」+「跳到已缓冲的位置是即时的」 | 无;跳完自动消失 |

- 故障牌**不随 OSD 收起**:它是故障说明不是控件。
- 失败页上「换线路」**不在这里做**,跳去线路管理【用户定 2026-07-20】。

## 9. 手机扫码遥控【用户定 2026-09-14:第一版就做】

### 9.1 它是什么

电视出码、手机扫。电视在局域网里起一个小网页,**手机浏览器打开就是遥控器**,不用装 App。
用户原话(2026-07-21):「扫码就不应该只做这个登录功能……这个网页可以当遥控器使用操控软件」。

### 9.2 手机网页五个标签

| 标签 | 能做什么 |
|---|---|
| 遥控 | 方向盘 + OK + 返回 + 首页;方向键按住每 220ms 连发(比电视端移焦节奏稍慢,免得冲过头) |
| 播放 | 片名 / 进度 / 暂停 / ±30s / ±10min / 停止;没在播时点按提示「现在没有在播放」 |
| 搜索 | **跨全部服务器**搜索(遥控器上最痛的场景),结果行「打开」→ 电视上直接进详情页 |
| 服务器 | 列表 / 切换 / 删除(手机上确认)/ **添加 Emby 服务器** / **批量添加** |
| 设置 | 音轨语言 · 字幕语言 · 默认开字幕 · 代理 · 清空缓存 · **弹幕屏蔽词** |

- 批量添加、屏蔽词这两样**只在手机页上好填**,电视上都是遥控器敲不动的长文本。
- 网页单文件、**不引任何外部资源**(局域网可能没外网,CDN 一挂这页就是白的)。
- 页面可见时才轮询:播放标签 1 秒,其它 4 秒;切到后台即停。

### 9.3 核心层 `core/companion`(TODO C30,需要新做)

| 项 | 规格 |
|---|---|
| 监听 | 局域网网卡,随机端口;**独立监听器**,不挂在只绑回环的 `localserve` 上 |
| 路径 | `/c/<12 位随机 token>`,其它路径一律 404 不透露信息;API 只收 POST |
| 默认 | **开**(`core/config/config.go` 的 `CompanionEnabled` 默认 true)。☠ `SPEC.md` §5 那句「开关默认关」与此矛盾,以本条为准并改掉 SPEC |
| 关再开 | 换新 token,旧码作废 |
| 拿不到局域网地址 | **不算失败**:服务照起,状态里带 `ip_error` 和端口 |
| 明文 HTTP | 与同 Wi-Fi 下访问自建 Emby 同档风险;不上自签 TLS(手机浏览器弹警告会把用户教成无视警告) |
| 状态命令 | 返回 `{enabled, running, url, port, error}` —— **不许只回一个可空 URL**(旧版因此只能猜「没开或没联网」) |
| 业务 | 直接调**同一批**核心层命令,不抄第二份(抄了就会分叉:手机上改的设置和电视上改的走两套代码) |

### 9.4 电视这一侧

- **按键注入**:核心层发事件 → 方向键走 `FocusManager.moveFocus(方向)`;确认 / 返回走**和真遥控器同一个分发入口**(§3.4),不另写一套。
- **打开条目**:事件带 `server_id` 且不是当前服务器 → 先切服务器再进详情页。
- **账号表变了**(手机上加 / 删 / 切服务器):复用现有 `account.status` 事件 → `AppState` 失效 `accounts` → 首次启动页自己换走。
  ☠ 旧版漏发这个广播:手机上登录成功,电视还停在「添加服务器」那一屏。
- **正在播放的片名**:播放页起播 / 离页时报给核心层(播放器状态里只有时间没有片名),离页清空,否则手机上一直挂着上一部。

|---|---|
| 冷启动到首页骨架 | ≤ 1.5 s |
| 冷启动到首页首行有图 | ≤ 3 s |
| 焦点移动 | 60fps,**长按方向键连续移动不掉帧** |
| 返回上一页到内容可见 | ≤ 200 ms(靠 `PageCache` 留存,不重新骨架化) |
| 常驻内存 | ≤ 200 MB(不含播放器解码缓冲) |

**落法**

- 图片按显示高度取档(`AppState.imageUrl` 已有的 120/220/330/480/720/1080 档):海报取 330、横卡取 180、Hero 取 720、详情背景取 1080。
- Hero 5 张背景图预挂,**其它地方只挂可见的**;Coil 内存缓存按屏数算,不无限。
- 行高度写成常量(`LazyRow` 嵌 `LazyColumn` 不给定高,每次测量重排整列 —— 手机「首页滑不动」的 Compose 形态)。
- **不做**:模糊、动画阴影、骨架闪光、全屏渐变、常驻动效(Hero 除了轮播淡化不做 Ken Burns)。
- 跑马灯**只在聚焦项上跑**。
- 弹幕层默认关;开着时【待真机】在盒子上量帧率,掉到 50fps 以下就把「合并重复」默认打开。

## 12. 旧 TV 的补丁,不继承

旧 TV 是 WebView + 第三方空间导航库。下面这些补丁**存在的唯一理由是那套技术栈**,Compose 下一行都不写;
**右列是它背后仍然成立的产品约束**,那部分已经写进本文对应章节。

| 旧补丁 | 根因 | 仍然成立的约束 |
|---|---|---|
| 1920 基准 `zoom` + gBCR / transform 单位换算 | CSS 双坐标系 | 数字按 960×540dp 定(§1.1) |
| 横向行 `padding:32px 0; margin:-32px 0` → 紧跟横向行的间距必须 > 32px | 空间导航库按 DOM 矩形筛候选,矩形被撑高 32px | 焦点放大不许被裁(§4.3) |
| 版本行按 ↓ 捕获阶段拦截 + 手抄 keyCode 表 | 库的斜向惩罚压不过 4px 角距 | 版本行 ↓ 必须落到集数栏(§7.6,用 `focusProperties`) |
| 手写横纵滚动 + `FOCUS_PAD` + `scroll.ts` | 没有原生「滚到焦点」 | 往上对齐段顶、首段贴真顶(§4.3) |
| 容器必须 focusable / 边界必须套 Provider / `saveLastFocusedChild` | 库机制 | 面板圈住焦点、行内记忆焦点(§4.2) |
| 厂商 keyCode 并集 + 壳转发 BACK / MENU / 媒体键 | WebView 收不到这些键 | 返回单一出口、媒体键可用(§3.4、§4.4) |
| 输入框 stopPropagation / blur 收输入法 / 卸载时提交 | 库在 window 冒泡监听;WebView 输入法只认 DOM 焦点 | 焦点框即输入框、离页提交(§4.5) |
| 手机遥控合成 KeyboardEvent + `defineProperty` 塞 keyCode | 库没有公开的方向导航 API | 手机按键和真遥控器走同一条路(§9.4) |
| 页面各持副本 + `lp://accounts-changed` 广播 | React 各页 useState | 手机改账号电视立即换屏(§9.4) |
| `html.playing` 三层背景透明 | WebView 叠在 SurfaceView 上 | 播放页 UI 层不画铺满底色(§8.1) |
| `@media (hover:hover)` | D-pad 移动误报 hover | — |
| `.pitem` 的 `min-height` + `overflow-wrap:anywhere` | CSS 断行 | 面板项随内容长高,长文件名换行(§5.3) |

### 13.3 出包与风险
