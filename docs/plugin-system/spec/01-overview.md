# 1. 总览

## 1.1 要做成什么

LinPlayer 的插件系统要给第三方**足够大的自由度**:不止加几个按钮,而是能

- **改 UI**:往官方页面插区块、替换区块、整页接管任意页面(凭据页与插件管理页除外),换主题、换壁纸、换播放控制栏(D4 D6 D14 D29);
- **引入外部数据源**:资源站、TVBox 生态、直播源,在界面上和 Emby 服务器平起平坐(D8 D10 D24);
- **扩展现有功能**:弹幕、字幕、元数据、下载、片头片尾、进度条预览图、「下一个播什么」的提供者(D8 D25 D537 D538 D244);
- **驱动播放器**:任意 mpv 属性/命令透传、自带着色器(D32);
- **接入系统**:命令面板、快捷键、手势、深链、分享、文件关联、通知、后台任务、桌面小组件、托盘(第 12 章)。

插件用 JS/TS 写(D3)。作者分三类(D1):写代码的社区开发者、只会填规则的普通用户(drpy 规则,D22 D120)、把现有生态搬过来的人(只做 TVBox 系,D2)。

## 1.3 原则

1. **不必要的不内置,做成插件。** 宿主只放「插件做不了」或「所有人都要」的能力(DECISIONS §0)。直播、TVBox 兼容、调试面板、字幕翻译、Trakt/Bangumi 同步都是官方插件(D124 D125);排行榜与付费追剧日历因为要用编译期密钥,留在宿主(D361)。
2. **完全信任,只守凭据。** 装了就是全权限;唯一不让碰的是 Emby 凭据与未声明的局域网访问(第 3 章)。
3. **声明在 manifest,实现在代码。** 不执行代码就能列出贡献点、冲突、设置项,用到才加载(D34)。
4. **宿主兜底,插件写坏不连累用户。** 超时打断、连错自动禁用、连崩安全模式、区块级错误边界、钩子超时跳过(D12 D53 D136 D281)。
5. **用户说了算。** 接管位冲突、钩子顺序、按键冲突、元数据优先级都由用户在设置里选或拖(D15 D76 D280 D64)。
6. **三端一套契约,各端原生渲染。** 插件写一次 JSX,Avalonia 与 Compose 各自原生画(D23 D44)。主题例外:分端做(D210)。

## 1.4 术语

| 术语 | 含义 |
|---|---|
| 宿主 | LinPlayer 本体:Go 核心层 + 两个 UI 壳(C# Avalonia 桌面、Kotlin Compose Android 手机/TV) |
| 插件 | 一个 `.lpplugin` 包,id 形如 `作者/名字`(D47) |
| 运行时 | 一个 goja 实例 + 一个事件循环;每插件一个主运行时(D52) |
| 子运行时 | 插件通过宿主 API 创建的隔离 goja,可同步请求(D127) |
| 贡献点 | 插件在 manifest 里声明、在代码里实现的扩展(D34) |
| 接管位 | 同一时刻只能有一个实现生效的位置,冲突时用户选(D15),如首页、播放控制栏、主题 |
| 注入位 | 多个插件可以同时往里加东西的位置,如侧栏入口、首页栏目、详情页区块 |
| 锚点 | 官方页面区块的稳定名字,插件可插在其前后或替换/隐藏它(D155 D159) |
| 钩子 | 宿主在某个流程中同步询问插件的回调:导航拦截、列表变换、卡片角标、命令补全(D277 D278 D474 D520) |
| 提供者 | 给官方功能供数据的扩展点:弹幕源、字幕、元数据、下载后端、EPG…(第 10 章) |
| 数据源 | 插件提供的「服务器」,和 Emby 并列(D10) |
| 通道 | 宿主注册表里的一条命名数据流,插件间互通只走它(D237 D273) |
| 统一结构 | 宿主定义的条目数据结构,Emby 与数据源共用(D92 D254) |
| 开放键 | 数据源的全局标识 `plugin:作者/名字/源id`(D153) |
| 扩展组件 | 宿主可下载的大件原生运行物:补帧、jar 环境、Python、GeckoView、whisper/ffmpeg(D380) |

## 1.5 怎么读

- 实现某块功能:读对应章 → 读 `api/plugin-sdk.d.ts` 里同名命名空间 → 在 `COVERAGE.md` 查涉及的 D 编号有没有漏。
- 每条规格后面括号里的 `Dnnn` 是出处。**实现时发现规格说不通,先回 DECISIONS.md 看原话**;原话也说不通,停下来问,不要自己改设计。
- 本文所有数字(超时、上限、间隔)汇总在附录 20.1,改数字两处同改。
