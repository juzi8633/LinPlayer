# 15. 官方仓库、Pages 站与 CI

## 15.1 仓库(D149 D410 D518 D519)

- 官方插件仓库 = 用户 GitHub 上**现有的插件仓库,清空后整仓重建**。清空是破坏性操作,**动手前再向用户确认一次**;清空时不动仓库的 Pages 设置(D395)。
- 一个仓库装全部:官方插件源码 + 官方市场索引 + SDK + CLI 包装 + 站点 + 文档,pnpm workspace:

```
plugins/<名字>/        官方插件,各自独立发版(D412)
packages/sdk/          @linplayer/plugin-sdk(类型 + JSON Schema);.d.ts 由主仓库随应用发版同步进来(D410)
packages/cli/          @linplayer/cli,按平台装 lp 二进制(D308)
site/                  Astro 站:插件墙 + 开发者文档(Starlight)(D405)
registry/index.json    官方市场索引(D28)
docs/                  开发者文档源,中英双语(D150 D399)
examples/              每个扩展点一个几十行的最小示例(D151)
```

- **许可证**:**整仓 AGPL-3.0-or-later**(与主仓库一致,D566 推翻 D519 的分法);第三方插件随作者定。
  这同时解掉了 D519 标出来的卡点:`lp` 复用主仓库(AGPL)的宿主代码,按 MIT 发布本来需要版权人另行授权。
  ☠ `@linplayer/plugin-sdk` 的 README 要写清**这不要求第三方插件也用 AGPL** ——
  那个包只提供类型(`.d.ts` 构建时被擦掉,运行时由宿主注入),不进插件产物。不写会劝退作者。
- 官方插件开源并接受 PR,维护者审合(D518)。

## 15.2 上架与更新流程(D83 D290 D294 D295)

1. 作者在自己的仓库开发、`lp pack` 出 `.lpplugin`、发 GitHub Release。
2. **首次上架**:Fork 官方仓库,改 `registry/index.json` 加自己的条目(`lp submit` 生成 JSON 片段,D484),提 PR;维护者人工看一遍合并。
3. **后续更新**:作者直接提 PR 改自己的条目。CI 校验全过就**自动合并**:只改自己 id 的条目 + 提交者是该作者 + 包能下载、manifest 合法、版本递增 + 下列校验。任一不满足留给维护者。
4. 合并时 CI 把包**复制进官方仓库 Releases**,index 里的地址指向官方副本:作者删仓/换包不影响已上架版本,下载量在一处统计。
   全部插件共用**一条** Release(tag `plugins`,D572)—— 一个插件一条的话 Release 页很快变成一堵墙,
   而用户在那页上找的是「应用的新版本」。资产名带版本号,历史版本照样各有各的地址。
5. 不做下架标记与远程禁用(D296)。

## 15.3 CI 校验(D265 D266 D421 D483)

- manifest 合法(过 JSON Schema)+ 版本 semver 且递增;
- 作者名 = PR 提交者 GitHub 用户名;`linplayer/` 前缀只许维护者;
- 包能安装加载:CI 里用 `lp` 真装一遍、执行 `activate` 不报错;
- 解压安全(路径穿越、压缩炸弹);
- `repository` 指向的源码仓库公开可访问;
- manifest 声明的贡献点在代码里有实现。

`lp check` 在本地跑同一套(D484)。

## 15.4 定时任务(D240 D482)

每 6 小时:抓各插件源码仓库的 GitHub star、Releases 下载量、README,写回 `index.json` 与静态副本,重建 Pages;合并 PR 时立即重建。

## 15.5 上架须知(D408)

写在仓库 README 与 Pages「上架指南」页,口吻以免责为主:插件由作者独立开发维护、官方不对插件内容负责;希望作者不在界面中投放广告或引流、不在用户不知情时上传其数据、公开源码、不内置指向未授权内容的站点(TVBox 插件本身不带任何源,内容由用户自行订阅);维护者保留不收录的权利。

## 15.6 GitHub Pages 站(D392~D406 D475~D480)

**构建**:CI 静态生成(pnpm + Astro),每个插件一个静态页,可被搜索引擎收录、分享链接有预览图、不耗 GitHub API 配额。**部署**:GitHub Actions 部署 Pages;沿用仓库**已配置的自定义域名**(存在 Pages 设置里)。仓库文件里不出现**未经裁决的**域名 —— 自有公开资产按 D565 豁免,名单在主仓库 `scripts/secrets-allow.txt`。不做访问统计。

**官方市场地址**:Pages 站在构建期把 `registry/index.json` 原样吐成 `/registry/index.json`,
客户端的编译期市场地址(`LP_PLUGIN_MARKET_URL`)指到它(D567)——
和插件墙读的是同一份源,分开托管迟早对不上。
☠ 那个端点在真索引不在时**必须让构建红**:站点为了能脱离 CI 单独构建会退回示例数据,
而市场地址一旦拿到示例,上架的插件下载地址全是假的,构建还全绿。

**信息架构**:
- 顶部导航:插件 / 文档 / 上架指南 / 下载 LinPlayer + 语言切换(中/英)+ 明暗切换(默认跟随系统)。
- 页脚:主仓库链接、上架须知、RSS。
- **首页第一屏就是插件墙**:一行搜索 + 分类 chip,下面卡片网格,不做宣传大头图。
- 筛选:分类 + 平台(Windows / Linux / Android 手机 / Android TV)+ 排序(下载量 / 最近更新 / star / 新上架)+ 只看官方 + 含付费功能显示/隐藏。
- 搜索:构建时生成索引,前端即时搜(名称/描述/作者/拼音首字母)。
- 卡片:以截图为主的横卡,有截图铺满卡面、悬停轮播,没截图用图标放大 + 模糊底;下方名称 / 作者 / 分类 / 下载量。
- 详情页:截图、README、贡献点清单、更新日志、下载量、star、历史版本及 `.lpplugin` 直链、支持平台 / 必需能力 / 所需组件 / minAppVersion、同作者其他插件;**一键安装**按钮(深链),2 秒没反应显示「没有反应?」→ 下载 LinPlayer / 手动下载包;**二维码**给手机扫。不做作者主页。
- 文档:Starlight(自带搜索、多语言、侧栏),视觉换成我们的;每个示例有「在 LinPlayer 中安装」按钮。
- 每个插件构建时生成一张分享预览图(图标 + 名称 + 一句描述 + 下载量)作 og:image。
- RSS/Atom:「新上架」「最近更新」两个 feed。
- 一篇「插件系统是什么、能做什么」介绍文章(随 2.0.0 发布,D415)。

**视觉**:与 LinPlayer 应用一脉 —— 深色玻璃、沿用应用 token(圆角 0/6/10/999、间距刻度、Accent 色);浅色另调一套玻璃与光斑;**不要 AI 味**(不用模板化渐变紫、千篇一律的居中大标题 + 三卡片);实现时用设计类 skill 辅助。

**动效**(全部尊重系统「减少动态效果」):卡片悬停上浮 + 滚动进入错落淡入;列表→详情共享元素过渡(View Transitions API);筛选/搜索时网格重排(FLIP);背景缓慢流动的暗色光斑/噪点。
